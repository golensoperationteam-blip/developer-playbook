# Technology Stack

## Languages

### Python
Preferred for AI, automation, data processing, scripts, orchestration, and backend experiments because of ecosystem depth and readability.

### Markdown
Preferred for human- and AI-readable documentation, knowledge repositories, SOPs, and project context.

### YAML / JSON
Preferred for configuration, registries, schemas, metadata, and machine-readable interchange.

## Platforms and Frameworks

### GitHub
Primary source-control and knowledge-repository platform for version history, documentation, collaboration, and AI-readable context.

### Shopify
Commerce platform context for store and product operations.

### Amazon
Marketplace context for listings, catalog, compliance, and product operations.

### IndiaMART
Marketplace context for seller catalog, category, keyword, and discovery operations.

### Canva
Visual-content and marketing creative workflow.

## Databases

No single database is formally the default yet. Select based on data model, query patterns, scale, transactions, cost, operations, and AI/search requirements. PostgreSQL is a strong default candidate for relational systems.

## Cloud Platforms

No single provider is formally preferred yet. Evaluate AWS, Azure, and GCP against integrations, cost, IAM/security, managed services, AI/ML services, deployment simplicity, expertise, and portability.

## Tools and Utilities

- GitHub — source control and knowledge
- Google Sheets — operational structured data
- Canva — visual content
- AI assistants/tools — research, drafting, analysis, automation
- Shopify/Amazon/IndiaMART — commerce execution

## Decision-Making Framework

1. Define the outcome.
2. Identify constraints: budget, time, data, security, scale.
3. Prefer existing tools when they already solve the problem.
4. Minimize unnecessary dependencies.
5. Choose the simplest architecture that can meet the known requirement.
6. Automate only after understanding the process.
7. Document non-obvious technology decisions.
8. Revisit decisions when requirements materially change.

## For AI Systems

This knowledge should be used for:
- Recommending technologies compatible with existing workflows
- Avoiding unnecessary tool changes
- Explaining trade-offs before proposing a new stack

Query examples:
- "Based on my stack, recommend a tool for [problem]"
